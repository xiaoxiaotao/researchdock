# 发布源码

1. 在当前私有工作区运行测试与验收。
2. 运行 `python scripts/build_release.py --check`；输出只显示文件路径与规则名，不回显疑似密钥。
3. 运行 `python scripts/build_release.py`，检查 `dist/researchdock/` 文件清单。
4. 从发布目录建立全新 Git 仓库，不复制旧历史。提交前核对 `git diff --cached --stat`。
5. 自行建立 GitHub 空仓库，推送后查看 CI，并按需要启用私密漏洞报告。

## 不发布的东西

私有数据目录、个人 config.yaml、`.env`、虚拟环境、CLI 安装及认证、密钥环、原件 PDF、模型回执、SQLite、导出报告、真实截图、私人调研文档、旧 Git 历史。

## 审查范围

脚本采用白名单与禁止后缀；清单外内容不进入 release。文本规则检查常见 API Key、个人绝对路径和认证字面量。它无法判断所有业务敏感内容；新增源码、测试和示例必须人工确认不含真实帖子、群 ID、分享 ID、联系方式或研究材料。

## 本机运行资料

打包不会删除本机资料，不会清除系统密钥环，也不会注销官方 CLI。发布包是独立源码副本；新用户启动后从空库开始。如果需要清理本机账户，那是另一项操作，不能与发布源码混为一谈。
