# Android 产品体验审查与下一轮优先级

## 审查范围

检查0.10客户端代码、移动镜像字段、桌面已有分析结构，以及真机首页和公司列表。以下是产品审查与实施建议，尚未作为新版本功能交付。不新增模型调用，不修改原始资料，不把未核实的观点变化当作事实。

## 核心判断

资料阅读和原件获取已有基础，但发现、跟踪、记录和回看尚未连接起来。当前用户仍需要自行判断先看哪篇、关注公司有什么进展、看完后怎样沉淀结论。继续增加按钮和配色不能单独解决这些问题。

## 已核实的问题

1. 当前移动Document协议只有摘要文本，没有桌面已有的`key_points`与`risks`。因此已有结构化分析没有在手机完整呈现。优先复用与当前归档修订一致的结果，不为排版重新调用模型；明确标注为已有AI整理，保留原文和来源。
2. `/v1/status`表示镜像变化，不能表示源站采集成功。手机“云端无新变更”不足以说明资料新鲜度。需要分别展示最后成功采集、云端发布、手机检查三个阶段的状态。
3. 首页以累计资料数和累计未读为主，缺少关注对象的新增材料与可执行的阅读队列。首屏同时放品牌、连接、同步、搜索、统计和筛选，资料主体出现较晚。
4. 摘要卡片没有充分区分正常正文、仅附件和正文不足；“原文未提供详细信息”之类说明占据大卡片，不能帮助挑选材料。应保留资料，压缩为空间更小的附件/待补充卡片。
5. 公司页默认按名称排序，已匹配上市公司、未上市研究对象、品牌及待核对名称混排。英文全名与多市场代码挤在同一按钮，缺少最近研究日期与关注优先。
6. 公司“调研时间线”目前以文章列表为主。桌面已有结构化观察、来源和部分比较逻辑没有进入手机协议；不能把仅按日期排列误称为已完成观点变化跟踪。
7. 已读与收藏主要解决存取，缺少稍后读、摘录、个人笔记和待验证问题；当前状态仍是设备本地状态。桌面与手机的收藏/笔记合并需要独立设计。
8. 原件有状态与重试，但没有统一下载任务中心、字节进度、取消和缓存管理。云端就绪与本机已下载必须继续区分。
9. 桌面财务模块没有对应的移动结构化协议；手机公司页尚无收入、利润、现金流的标准化概览。不能从研报段落金额拼成财务表。

## 建议实施顺序

| 轮次 | 交付内容 | 验收标准 |
| --- | --- | --- |
| P0：信息完整与可信 | 关键观点/风险提示卡片；端到端采集状态；仅附件/正文不足的卡片类型 | 旧修订分析不混用；采集失败不会显示为一切正常；附件帖不再堆砌空泛摘要 |
| P1：每日研究主线 | 首页展示关注对象新增、今日收录、继续阅读；关注公司优先与最近研究日期；压缩全局头部 | 打开即可找到关注公司新增材料；新增与发布日期口径清楚；返回和筛选继续保留 |
| P1：公司研究空间 | 公司概览、材料时间线、已有财务与来源入口；行业/公司关系回跳 | 财务显示报告期/币种/单位/来源；已有证据可回原文；不提供估值 |
| P2：阅读沉淀 | 稍后读、带修订与原文位置的摘录、个人笔记和待验证问题 | 可从公司页回看摘录及上下文；清晰区分模型摘要、原文证据与个人判断；跨设备同步另行验证 |
| P2：阅读与下载细节 | 下载中心、字节进度、重试/取消、缓存大小/清理、字号/行距/夜间模式 | 下载状态不遮挡阅读；清理不会删除收藏与笔记；后台行为和系统权限有明确边界 |

## 首页建议

紧凑品牌与搜索 → 采集状态摘要（异常可见）→ 关注公司新增 → 继续阅读 → 今日收录列表。资料总量、连接设置、详细筛选放到次级入口或展开区域。原有资料库仍可按行业、公司、来源和时间检索。

“今日收录”以首次入库时间计算，“今日发布”以源站发布时间计算；不能用当前同步时间替代历史发布日期。镜像sequence也会随摘要和附件变化，不能把所有sequence更新都算成新研报。新增材料首先采用确定性口径，不增加自动AI重要性评分。

## 公司空间建议

中文常用名/目录名称 + 市场与代码 → 关注状态与最近研究日期 → 新增材料/未读 → 调研材料时间线 → 财务概览 → 摘录与待验证问题。品牌和未上市对象仍保留研究入口，但与已匹配证券区分，不强行绑定股票代码。

时间线先展示清楚材料日期、发布机构、原文要点与附件。观点/指标比较只在公司、报告期、指标口径、单位、币种和来源足够明确时进行，给出原文证据；不同机构的不同判断不能直接标成同一机构改口。

## 本轮边界

本轮只交付审查结论及实施顺序，未发布新APK或声称上述候选功能已经完成。优先做P0与首页主线，再扩展跨端笔记、下载后台与财务细节。
