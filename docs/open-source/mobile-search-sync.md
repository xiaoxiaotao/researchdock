# 全文搜索与增量同步（0.15）

## 全文搜索

安卓搜索栏旁点击“全文”，输入至少两个字符。云端检索已归档正文、标题、公司/代码、行业与附件名称，返回原文片段、来源、日期及修订；可按当前公司/行业/来源和日期过滤，或清除范围。结果默认最多40条，超过时提示缩小范围。标题/正文命中可进入原有完整阅读器并突出首个匹配，返回保留搜索结果。

本机模式只查仍在目录中、正文缓存与目录修订一致的资料；网络连接失败时明确回退到这个较小范围。鉴权失败或接口尚未升级不会伪装成成功的全库搜索。不同格式的PDF、图像及音频仍只检索标题/附件名，不做解析、OCR或转写。普通目录输入框继续提供快速元数据筛选。

云端采用SQLite FTS5 trigram索引，三字符以上按字面词句检索；双字符使用转义的LIKE匹配。输入不解释为FTS运算表达式，不调用模型、不引入向量服务。高亮位置明确区分Unicode码点与Android UTF-16位置，避免emoji导致引句错位。

## 目录同步

`GET /v1/catalog`仅允许阅读凭据访问，包含两个模式：

- `snapshot`：首次同步时固定cursor，按document_id继续分页。每条记录读取截止该cursor的最后一次不可变元数据，期间新增/修改/删除不会移动已选分页。
- `delta`：按sequence接续读取截止同一cursor的变更，含新增/更新和删除事件。客户端完整收集、校验后才写目录并推进游标；失败保留旧目录。

云端保留原有接口，旧客户端可继续使用。新客户端在`/v1/status`发现`catalog_protocol:2`后首次做一致性全量同步，之后使用增量；尚未升级的服务仍使用原协议。保存的游标超过服务端水位、早于迁移基线时返回409，新客户端重新获取快照。资料库为空也有固定的零水位语义。

旧数据库首次请求会事务性迁移：保留所有资料与原文，回填当前元数据、建立全文索引，旧历史游标需要重新全量同步。若回退旧服务后又写入无日志内容的变更，下次新服务会重建当前索引并提升基线，要求旧游标重新同步。无需重新从信源获取或重新调用DeepSeek。

正文修订规则、原文不可改写约束、原件授权、阅读状态和红色主题继续保留。搜索和目录响应设置`Cache-Control: private, no-store`。新索引只处理现有私有云副本，不发送资料到第三方搜索服务。

## 验证重点

- 同步翻页期间新增、修订和删除，当前快照不漏不重，后续增量能接续。
- 旧数据库迁移、服务回退后的索引恢复、无效游标、空分页保护和失败时不提交部分目录。
- 无摘要正文可搜，双字符/字面运算符/特殊符号/emoji偏移、过滤条件及删除后不再命中。
- 本机检索不暴露已从目录删除的缓存或旧修订；结果回原文定位后能返回同一搜索页面。

本版本未加入跨设备个人笔记/收藏合并或后台通知；这些仍需独立的使用者身份、权限及冲突处理设计。
