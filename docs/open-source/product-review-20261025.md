# 研迹产品调研与整体优化 · 2026-10-25

## 目标与调研范围

产品定位：私人财经研究资料库。Mac 负责采集与已有分析，手机用于发现、跟踪、阅读和回看。保持行业分类、公司时间线、来源可追溯；不增加估值、音频转写或额外模型评分。本次调研公开产品页、官方说明和开源仓库，并检查了 Reportify 未登录页面的实际导航。未体验付费后台，不将营销能力视为已实测结果。

| 产品 | 官方可观察的组织方式 | 对研迹的启发 | 当前轮次 |
|---|---|---|---|
| Readwise Reader | 阅读队列、过滤视图、继续阅读、排版设置 | 阅读状态成为主要入口，而非只有时间倒序 | 未读、续读、来源与日期筛选；阅读位置保存 |
| Quartr | 围绕公司组织关注、事件、资料与历史对比 | 公司是研究对象，材料是证据 | 公司关注、本机关注资料流、日期分组 |
| Koyfin | 公司概览集中展示资料，关注清单可定制 | 在公司空间汇总，先看覆盖范围，再看材料 | 公司资料数与未读数；不引入估值 |
| Reportify | 当前公开页以研究问题、文档搜索、任务、知识库为入口 | 从研究问题走向原文，避免文件堆积 | 先改善公司/行业与原文之间的导航；不复制付费智能体 |
| AIHOT | 同一事件多源聚合，主题入口与日报体系 | 减少重复曝光，体现信息进展 | 后续候选，当前不冒进合并原始研报 |
| Read You / Readest | 阅读层次、分类与排版强调 | 少量强调色，阅读操作集中 | 延续原生富文本，增加目录与紧凑链接 |

## 各产品的工作流与取舍

### Readwise Reader

官方说明将内容组织为阅读队列，并提供未读、近期新增等过滤视图；排版与阅读状态互相配合。对我们最有用的是“打开后从上次位置继续”，以及少量容易理解的筛选。研迹采用“全部／未读／续读／关注”入口，不照搬复杂过滤语法；目前状态只保存在本机，不宣称跨端同步。

来源：[阅读队列](https://docs.readwise.io/reader/guides/workflows/library-configuration)、[默认过滤视图](https://docs.readwise.io/reader/guides/filtering/default-views)、[继续阅读示例](https://docs.readwise.io/reader/guides/filtering/query-examples)、[排版设置](https://docs.readwise.io/reader/docs/faqs/appearance)。

### Quartr

官方产品将公司关注、事件资料和历史对照连在一起。我们可借鉴“公司→不同日期的证据”的路径。当前原文库先建立按发布日期分组的时间线，并允许关注公司；不把文章数量误称为真实事件数量。自动识别“观点变化”需要明确证据与对照基准，应单独实现并验证。

来源：[功能总览](https://quartr.com/features)、[关注清单](https://quartr.com/features/watchlists)、[历史材料对照](https://quartr.com/features/slide-history-comparison)、[移动产品](https://quartr.com/products/mobile-app)。

### Koyfin

公司概览和关注清单将分散的信息集中到研究对象。研迹已有桌面公司财务功能，手机目前的镜像协议没有结构化财务表；这轮只显示真实资料覆盖、未读数和时间线，不伪造财务面板，也不从原文金额猜测财务口径。手机财务页后续需要独立的报告期、币种、单位、来源字段。

来源：[公司概览](https://www.koyfin.com/features/company-snapshots/)、[关注清单](https://www.koyfin.com/features/watchlists/)。

### Reportify

2026-10-25 可访问的公开页以智能体和研究任务为主，侧栏包含关注、知识库等入口，不能继续把它当作过去的纯研报列表。可取之处是把研究问题与资料连接起来。当前不引入对话首页，避免每次浏览触发模型；先让人能通过公司和行业找齐资料，再进入原文。未登录知识库和付费输出未做验证。

来源：[当前公开产品](https://reportify.cn/)。

### AIHOT

开源 README 描述多源内容聚合及热点编排，也包含多轮模型筛选与评分。研迹借鉴主题与进展的组织思路，但不复制整套高调用量流程。先做确定性导航；后续聚合要保留所有来源，并区分“同文转载”和“同公司不同观点”，不因标题相似就删除或合并研报。

来源：[官方仓库与 README](https://github.com/KKKKhazix/AIHOT)。未复制其代码、品牌或字体。

### Read You / Readest

两者可用于观察移动阅读的层次与排版思路。研迹继续采用自己的原生组件，保留现有安全连接；新增目录定位，长链接用可点击的来源标签呈现，实际 URL 保存在链接对象与原始归档中。页面不会主动向外部站点下载远程图片。

来源：[Read You](https://github.com/ReadYouApp/ReadYou)、[Readest](https://github.com/readest/readest)。未复制第三方代码。

## 产品结构

- 首页：资料覆盖与待阅读数量；全部、未读、续读、关注；日期和来源筛选；继续上次阅读。
- 行业：现有双列入口，资料数可见，点击进入材料列表。
- 公司：资料数、未读数、关注操作；进入后按日期分组展示材料，显示筛选条件。
- 原件：PDF 原件阅读，遵守只展示已缓存资源的边界。
- 收藏：本机收藏，状态不与桌面混淆。
- 阅读：标题、来源与摘要→章节目录→原文→附件与来源。恢复当前修订的滚动比例；全文原始 URL 不再占满屏幕。

## 本轮完成边界与后续

本轮实现集中在 Android 的研究入口和阅读工作流；桌面已有财务页与公司证据功能保持运行。新增功能不产生模型调用、不修改原始文档、不改变云端鉴权协议。

后续需独立设计和验证：手机结构化财务页、跨端收藏与批注、保守的事件去重、推送与后台同步、端到端资料加密。上述功能不能因本轮界面升级就宣称完成。

验收应使用真实资料而非只看样例：筛选结果、公司关注、日期分组、目录跳转、关闭再打开续读、长链接可点击且原 URL 保留、字号调整后仍可继续阅读；确认固定签名覆盖更新保留本机状态。
