# 连续阅读修复（Android 0.11.3）

## 安卓

原先在联网读取正文前就写入已读状态，网络失败也会误标为已读。现在只有当前请求成功且正文进入阅读页后才写入。离线失败保留未读，过期请求不修改已读，也不覆盖新页面。

正文缓存文件读取、JSON 解析和元数据合并移到独立的两个后台线程，减少主线程磁盘操作；列表同步不阻止读取本地已有正文。每次打开有独立请求序号，切换页面或打开另一篇后，旧请求的显示回调失效。连接设置等待活动正文请求完成，避免切换服务时混入旧请求的缓存。

新增真机回归：无效连接下打开失败仍未读；列表正在同步时，缓存正文仍可打开并正确标记已读。测试仅使用合成资料，结束后恢复连接配置与阅读状态。

## Mac

阅读位置从整页百分比改为原文段落索引和段内偏移，仍按文档与修订隔离。切换专注模式、修改字号时先记录段落，再按新布局恢复；重新打开时可点击继续阅读。兼容旧版百分比记录。文章顶部不强制跳到正文，明确的章节/证据链接仍优先于自动跳转。正文修改、新修订不沿用旧修订的段落位置。

浏览器验收中，切换专注前后均停留在相同段落，段内比例一致；字号调整后的差异仅为像素取整。此功能保存在当前浏览器，不作为跨设备同步承诺。

## 服务

阅读详情页复用已有16 MiB预算的归档解析缓存，继续通过文件状态校验有效性。Markdown渲染、证据定位、历史版本选择和当前分析状态仍按请求处理，不把这些动态结果缓存成旧页面。不增加模型调用。
